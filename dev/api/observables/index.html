DynamicalCorrelators.evolve_mps — Function
evolve_mps(H::MPOHamiltonian, ts::AbstractVector,
           rho_mps::FiniteMPS=convert(FiniteMPS, identityMPO(H)); kwargs...)

Evolve rho_mps through the time grid ts under a time-independent Hamiltonian H.

The first n recorded steps use tdvp2 and later steps use tdvp1. Saved states are written to filename for every index in save_id with keys "t=$(ts[i])". Set save = false to disable all file output. For finite-temperature dcorrelator, save every requested real-time slice, for example save_id = eachindex(times).

The TDVP environments are managed by the fast finite engine (HalfFiniteEnvironments); pass disk = true (or a directory path) to back them by disk instead of RAM.

source
evolve_mps(H::Function, ts::AbstractVector, mus::AbstractVector,
           rho_mps::FiniteMPS=convert(FiniteMPS, identityMPO(H(mus[1]))); kwargs...)

Evolve rho_mps through ts under a time-dependent Hamiltonian H(mu).

At step i, the Hamiltonian is rebuilt as H(mus[i]). Saved states and the corresponding parameter values are written to filename with keys "t=$(ts[i])" and "mu_t=$(ts[i])". Set save = false to disable all file output. For finite-temperature dcorrelator, save every requested real-time slice, for example save_id = eachindex(times).

The TDVP environments are managed by the fast finite engine (HalfFiniteEnvironments); pass disk = true (or a directory path) to back them by disk instead of RAM. Note that the environments are built once from H(mus[1]) and kept for the whole evolution — the same behavior as before, when MPSKit's environments were reused across the changing Hamiltonian.

DynamicalCorrelators.dcorrelator — Function
dcorrelator(gs::FiniteNormalMPS, H::MPOHamiltonian,
            op::AbstractTensorMap, id::Integer; kwargs...)

Compute a zero-temperature dynamical correlation from one source site.

Gorkov Green's function:

G_ij(t) =-i[
            ⟨{c_i(t),  c_j†(0)}⟩     ⟨{c_i(t),  c_j(0)}⟩
            ⟨{c_i†(t), c_j†(0)}⟩     ⟨{c_i†(t), c_j(0)}⟩]

G11_ij(t) = -i(⟨c_i(t)c_j†(0)⟩ + ⟨c_j†(0)c_i(t)⟩)
        = -im*(exp(iE₀t)*dot(c_i†|0⟩, exp(-iHt)c_j†|0⟩) + exp(-iE₀t)*dot(exp(-iHt)c_j|0⟩, c_i|0⟩))
        = -im*(exp(iE₀t)*dot(c_i†|0⟩, exp(-iHt)c_j†|0⟩) + exp(-iE₀t)*conj(dot(c_i|0⟩, exp(-iHt)c_j|0⟩)))

G12_ij(t) = -i(⟨c_i(t)c_j(0)⟩ + ⟨c_j(0)c_i(t)⟩)
        = -im*(exp(iE₀t)*dot(c_i†|0⟩, exp(-iHt)c_j|0⟩) + exp(-iE₀t)*dot(exp(-iHt)c_j†|0⟩, c_i|0⟩))
        = -im*(exp(iE₀t)*dot(c_i†|0⟩, exp(-iHt)c_j|0⟩) + exp(-iE₀t)*conj(dot(c_i|0⟩, exp(-iHt)c_j†|0⟩)))

G21_ij(t) = -i(⟨c_i†(t)c_j†(0)⟩ + ⟨c_j†(0)c_i†(t)⟩)
        = -im*(exp(iE₀t)*dot(c_i|0⟩, exp(-iHt)c_j†|0⟩) + exp(-iE₀t)*dot(exp(-iHt)c_j|0⟩, c_i†|0⟩))
        = -im*(exp(iE₀t)*dot(c_i|0⟩, exp(-iHt)c_j†|0⟩) + exp(-iE₀t)*conj(dot(c_i†|0⟩, exp(-iHt)c_j|0⟩)))

G22_ij(t) = -i(⟨c_i†(t)c_j(0)⟩ + ⟨c_j(0)c_i†(t)⟩)
        = -im*(exp(iE₀t)*dot(c_i|0⟩, exp(-iHt)c_j|0⟩) + exp(-iE₀t)*dot(exp(-iHt)c_j†|0⟩, c_i†|0⟩))
        = -im*(exp(iE₀t)*dot(c_i|0⟩, exp(-iHt)c_j|0⟩) + exp(-iE₀t)*conj(dot(c_i†|0⟩, exp(-iHt)c_j†|0⟩)))

id selects the source channel. Values 1:length(H) use the greater contribution, while length(H)+1:2length(H) use the lesser term in the retarded combination. Only record_indices are returned, and the evolution stops at the last requested record. This single-source method uses ordinary arrays and does not start a distributed SharedArray calculation. When anomalous is a TensorMap, the same evolved source ket is projected with both op and anomalous, and a NamedTuple (G11, G12, G21, G22) is returned. Results are always recomputed: existing files are overwritten, never reused. Set save = false to disable all file output.

Note:  the relation for spin-U(1) Green' function and spin-SU(2) Green's function
        assuming the form of spin-U(1) Green' function is:
    G_ij(t) =-i[
                ⟨{c_i↓(t),  c_j†↓(0)}⟩         0                         0              ⟨{c_i↓(t),  c_j↑(0)}⟩
                            0           ⟨{c_i↑(t),  c_j†↑(0)}⟩  ⟨{c_i↑(t),  c_j↓(0)}⟩            0
                                        ⟨{c_i†↓(t),  c_j†↑(0)}⟩ ⟨{c_i†↓(t),  c_j↓(0)}⟩           0
                ⟨{c_i†↑(t),  c_j†↓(0)}⟩        0                        0               ⟨{c_i†↑(t),  c_j↑(0)}⟩]
        then we have:
        Gu₁[1,1] + Gu₁[2,2] == Gsu₂[1,1]; Gsu₂[1,1]/2 == Gu₁[1,1]
        Gu₁[2,3] - Gu₁[1,4] == Gsu₂[1,2]; Gsu₂[1,2]/2 == Gu₁[2,3]
        Gu₁[3,2] - Gu₁[4,1] == Gsu₂[2,1]; Gsu₂[2,1]/2 == Gu₁[3,2]
        Gu₁[3,3] + Gu₁[4,4] == Gsu₂[2,2]; Gsu₂[3,3]/2 == Gu₁[2,2]

Internal keywords used by the low-lying-removal wrapper (see `lehmann.jl`):
`source` replaces the chargedMPS construction (the given state is evolved
as the ket instead), `gf_low` is an analytic correlator contribution added
slice by slice on the recorded grid (a matrix, or a `(; G11, G12, G21,
G22)` NamedTuple for Gorkov runs), and `lowlying` is a NamedTuple saved
into the output file under `"lowlying_<key>"` entries.

dcorrelator(gs::FiniteNormalMPS, H::MPOHamiltonian, op::AbstractTensorMap,
            id::Integer, excited::AbstractVector{<:FiniteMPS}; kwargs...)

Zero-temperature dynamical correlation from one source site with removal of low-lying states (Paeckel et al., Ann. Phys. 411, 167998 (2019), Sec. 7.3).

The charged state ket = chargedMPO(op, idx) * gs is decomposed into the subspace spanned by the precomputed eigenstates excited of the charged sector and a remainder: ket = Σₙ cₙ ψₙ + rest. Only rest is time-evolved with MPS/TDVP; the removed components are propagated analytically through their eigen-energies (Lehmann part) and added back slice by slice, so the returned total correlator is identical in exact arithmetic — but the evolved part no longer contains the slowest oscillations. Since excited must live in the sector reached by op, creation-operator runs (id ≤ L) and annihilation-operator runs (id > L) each take their own set of states, typically from separate excited_states runs saved to disk.

Additional keywords

  • energies = nothing: precomputed energies of excited; computed from expectation_value(ψₙ, H) when omitted.
  • overlap_abstol = 1e-10: threshold on |cₙ|² for the overlap pre-check. The exact overlaps are computed upfront through MPSKit's three-argument dot (no chargedMPS compression) and printed. If every state is below the threshold for the source, an ArgumentError is thrown before anything expensive happens — compute more excited states.
  • overlap_warn_fraction = 0.5: warn (without aborting) when at least this fraction of the states is below overlap_abstol.
  • orth_tol = 1e-6: the input states are checked for orthonormality, which the projection formula relies on.
  • compress_rest = true, rest_trunc = truncerror(; rtol=1e-10): the remainder is built by exact direct sums followed by zip-up compression with this truncation (pass e.g. truncrank(D) to cap the bond dimension).
  • skip_rest_tol = 1e-12: if ‖rest‖²/‖ket‖² falls below this, the time evolution is skipped and the pure Lehmann result returned.
  • tmax_check = true, eta = nothing: warn when times max is below the recommended evolution window (see recommend_tmax); passing the broadening eta additionally enables the 2π/η resolution-floor warning.

Returns a NamedTuple (; gf, gf_low, gf_rest, cs, ds, dE, E0) with the total, the analytic Lehmann part and the evolved remainder part (apply linear prediction to gf_rest only, then re-add lehmann_eval on the extended grid). Saved files keep the regular format with the total in "pro_r", plus "lowlying_cs" / "lowlying_ds" / "lowlying_dE" entries. With anomalous, gf, gf_low and gf_rest are NamedTuples (; G11, G12, G21, G22).

source
dcorrelator(gs::FiniteNormalMPS, H::MPOHamiltonian, op::AbstractTensorMap,
            indices::AbstractArray, excited::AbstractVector{<:FiniteMPS}; kwargs...)

Multi-source version of the low-lying-removal dcorrelator: the source channels in indices are evaluated in parallel with Distributed and stored in a SharedArray. The same excited states are reused for every source — the overlap pre-check runs for all sources on the main process first (failing fast, before any time evolution), and the source-independent measurement vectors dₙ = sweep_dot(gs, op, ψₙ) are computed only once. Keywords and the returned NamedTuple follow the single-source method, with gf, gf_low, gf_rest of size (length(H), length(indices), length(record_indices)) and cs of size (length(excited), length(indices)).

source
dcorrelator(gs::FiniteNormalMPS, H::MPOHamiltonian, op::AbstractTensorMap;
            times, block, kwargs...)

Zero-temperature dynamical correlator with the time-split (meet-in-the-middle) scheme. Both sides of the operator sandwich are evolved to half the requested time:

greater (block = :greater, op = creation operator):
    gf[i, j, r] = -im * e^{+i E0 tᵣ} * <a_i(tᵣ/2) | b_j(tᵣ/2)>
lesser (block = :lesser, op = annihilation operator):
    gf[i, j, r] = -im * e^{-i E0 tᵣ} * conj(<e_i(tᵣ/2) | d_j(tᵣ/2)>)

with |a_i(τ)> = e^{+iHτ} c†_i|0>, |b_j(τ)> = e^{-iHτ} c†_j|0> (greater) and |e_i(τ)> = e^{+iHτ} c_i|0>, |d_j(τ)> = e^{-iHτ} c_j|0> (lesser). The phase/conjugation conventions match the direct method exactly, so the retarded combination is assembled as before: gfxt = gf_greater .+ gf_lesser.

This three-positional-argument signature unambiguously selects the time-split method; the direct methods take a fourth positional id::Integer or indices::AbstractArray.

Differences from the direct method

  • The full length(H) × length(H) matrix of site pairs is computed at every slice; there is no indices argument — any missing row or column leaves the correlator incomplete, so the method always computes the whole matrix.
  • Each call computes one block. block = :greater takes the creation operator (charged states in the N+1 sector), block = :lesser the annihilation operator (N-1 sector). The two blocks are fully independent and can run as separate jobs.
  • 2 * length(H) fat states are kept in memory (both time directions of one block), versus length(H) kets plus cheap t = 0 bras in the direct method. The TDVP environments dominate the footprint; disk = true (or a directory) pages them to disk as usual, one random subdirectory per state.

Keywords

  • block::Symbol (required): :greater or :lesser.
  • times = 0:0.05:5.0: the correlator time grid. Internally the states evolve on times ./ 2, so the TDVP step is half the grid spacing.
  • record_indices: continuous window into times; evolution stops at the last recorded slice.
  • parallel_charged, parallel_tdvp2, parallel_tdvp1 (each defaults to Threads.nthreads()): per-phase caps on concurrent tasks. The chargedMPS compression and the first n two-site TDVP steps carry the large per-task workspaces (set by approxalg / tdvp2), while the hundreds of one-site steps that dominate the wall time are memory-light — so launch Julia with a large thread pool and throttle only the memory-hungry phases, e.g. parallel_charged ≈ 0.7 * RAM / per-compression-workspace. During evolution the bra and ket families step forward as one merged pool of 2 * length(H) tasks, so a single slow state idles at most one slot instead of stalling a whole family.
  • chargedmps_path: directory of cached charged states (default nothing = cache off). Files are named <tag>_i=NNN.jld2 with the zero-padded cache index NNN = site for block = :greater and L + site for block = :lesser, so one directory serves both blocks of the same model; tag is derived from approxalg (truncation, tol, maxiter). A present, readable file is used as-is: the cache is never validated against the model, gs or op — picking a matching directory is the caller's responsibility. Missing or unreadable files are recomputed and written back atomically (temp file + rename), so an interrupted run resumes the charged phase from the completed sites only.
  • hamiltonian_threads (default nothing = automatic): cap on the fan-out of the channel-split threaded Hamiltonian inside each matvec. With nothing, the cap is derived per phase as max(1, Threads.nthreads() ÷ outer concurrency), so the chargedMPS phase (few fat tasks) gets inner threading while the evolution phases (2L tasks in flight) run their matvecs serially — outer × inner never exceeds the thread pool. An integer overrides all phases with a fixed cap. The global cap is restored to its previous value when the call ends.
  • mode (default :threaded): :threaded runs everything in this process as described above. :distributed instead treats the 2L states as independent tasks over the existing Distributed.workers() — one state per worker process — communicating only through checkpoint files under workdir (required; fast shared storage). Workers are never launched by the package: add them in the driver script with the project activated and a single thread (exeflags = "--project=<env> -t1"), using whatever manager matches the cluster — LocalAffinityManager(np; mode = COMPACT) on one node, SlurmManager(np) / LSFManager(np) from ClusterManagers.jl for multi-node; the driver discovers the worker → host mapping itself and splits the states evenly across hosts, so any of them works unchanged. Two strict phases run: first the charged initial states (the memory peak of the whole run, throttled by charged_per_node), then all evolutions with one state per worker. Process isolation removes the shared-heap stop-the-world GC coupling that dominates the threaded driver at high thread counts, and every recorded slice is checkpointed, so a killed job (walltime, node failure) resumes from the last complete slice. The threaded-only knobs (parallel_charged/parallel_tdvp2/ parallel_tdvp1, hamiltonian_threads) are ignored in this mode. For production-size runs, split the job by memory profile with prepare_dcorrelator: a short, generously provisioned preparation job (charged states + the two-site TDVP window, no overlaps), then this lean call on the same workdir for the long one-site TDVP tail.
  • charged_per_node (default nothing, distributed mode only): how many chargedMPS computations may run concurrently per node during phase 1. Size it as node memory ÷ per-instance peak (e.g. ~8–12 for D = 5000 on a 384 GB node). nothing lifts the cap — fine when the chargedMPS cache hits (loads take seconds), dangerous on a cold cache: dozens of simultaneous compressions will exceed any node's memory. Ignored in :threaded mode.
  • backlog (default 2, distributed mode): how many recorded slices workers may run ahead of the master's overlap pass; at most backlog + 1 slices (each 2L states) occupy workdir at any time.
  • overlap_block (default 8, distributed mode): tile size of the master's thread-parallel overlap pass — at most 2 * overlap_block states are resident on the master.
  • keep_final_states (default true, distributed mode): keep the last slice's checkpoints (the τ = tmax/2 states) for reuse; false deletes them.
  • save, gf_path, disk, n, approxalg, tdvp1, tdvp2: same meaning as in the direct dcorrelator.

The charged-state setup, state evolutions, and all-pairs overlaps are parallelized with Threads.@threads :dynamic (dynamic scheduling: per-compression, per-state evolution, and per-pair overlap costs are all far from uniform). Start Julia with several threads and keep BLAS.set_num_threads small to avoid oversubscription.

With verbose = true, every recorded slice logs a small diagnostics block after the usual progress line, organized as an indented wall-clock tree: the serial phases (evolve / overlaps / other) add up to the slice duration; under evolve, the per-state breakdown of the TDVP sections (Krylov integration and nested matvec, Hamiltonian construction, gauge/expand, disk-backed environment reads, and the untimed remainder), preceded by per-kind AC/AC2/C matvec shares, actual Krylov dimensions and convergence counts, and followed by the compute / GC / safepoint-wait split of the phase wall. These tables are the first place to look when a slice is slower than expected.

Returns gf :: Array{ComplexF64,3} of size (length(H), length(H), length(record_indices)). With save = true, each recorded slice is appended to gf_split_start=<t0>_end=<t1>_block=<block>.jld2 under pro_<r>, together with the grid metadata.

Note: the low-lying-state (Lehmann) removal of Sec. 7.3 is not wired into this method yet; it will arrive as a separate dcorrelator method.

Fourier Transforms

DynamicalCorrelators.fourier_kw — Function
fourier_kw(gf_kt, ts, w, dampings; symmetrize=false)

Time Fourier transform of G(k, t) to G(k, ω) at a single frequency w, with pre-computed damping factors.

With symmetrize=false (default) this is the one-sided integral ∫₀ᵀ dt f(t) e^{iωt} G(k, t), whose imaginary part is generically nonzero on finite-time data. With symmetrize=±1, the conjugation symmetry G_{yx}(k, -t) = ±conj(G_{xy}(k, t)) is used to fold the two-sided integral onto the data window:

\[G_{xy}(k, \omega) = \int_0^T dt\, f(t) \big[ e^{i\omega t} G_{xy}(k, t) \pm e^{-i\omega t} G_{yx}(k, t)^* \big] .\]

The sign must match how the correlator was assembled:

  • symmetrize=true (i.e. +1): bare ⟨Aₓ(t) A†ᵧ(0)⟩ correlators without any retarded prefactor, which obey G(-t) = +conj(G(t)). The result is manifestly Hermitian in (x, y) at every ω and real on the diagonal.
  • symmetrize=-1: Green's functions carrying the retarded -im prefactor, which obey G(-t) = -conj(G(t)). This is the right choice for the output of dcorrelator, for both spin and electron operators. The result is manifestly anti-Hermitian with a purely imaginary diagonal, and the spectral function is -imag(diag)/2 (relative to the usual -imag(one-sided) convention).

When gf_kt is square (all source sites evolved), the conjugated partner is the transposed element G_{yx}(k, t) and the folding is exact. When gf_kt is rectangular (from fourier_kt with center), the transposed element was never computed, so each element is folded with its own conjugate, G_c(k, -t) = ±conj(G_c(k, t)); this relies on translation invariance of the displacement data around each source center, which is the same assumption under which the folded kernel is derived.

In both cases the result is the full two-sided transform (twice the corresponding quadrature of the one-sided one), and the unphysical truncation-induced component in the complementary quadrature is removed. ts must start at t = 0.

source
fourier_kw(gf_rt, rs, ts, ks, ws; mthreads=nthreads(), broadentype=(0.05, "G"), regroup=..., kernel=:exp, symmetrize=false)

Full double Fourier transform from G(r, t) to G(k, ω) over arrays of momenta ks and frequencies ws. Multi-threaded over frequencies.

Arguments

  • gf_rt: Green's function (N_mps, N_mps, N_times) (axis 1 = measurement site, axis 2 = source site), or (N_mps, length(center), N_times) when center is given.
  • rs: site position vectors.
  • ts: time range.
  • ks: array of momentum vectors.
  • ws: array of frequencies.
  • mthreads: number of threads (default: all available).
  • broadentype: broadening specification, e.g., (0.05, "G") for Gaussian with η=0.05, or (η, "GN") for the window-normalized Gaussian exp(-η·(t/tmax)^2) whose resolution improves as the time window grows (typical η ≈ 2 ~ 4).
  • regroup: groups of MPS site indices defining the physical channels of the transform, forwarded to fourier_kt — see its docstring for the grouping rules and recipes (single group for 1:1 site mappings, one group per orbital/leg across all unit cells for band resolution, one group per unit for coarse graining).
  • center: nothing (default) or the physical source-site indices when gf_rt was computed only for a subset of sources; forwarded to fourier_kt.
  • kernel: forwarded to fourier_kt; :exp (default) or :cos to keep only the inversion-symmetric cos(k·Δr) part of the spatial phase.
  • symmetrize: false (default), true/+1, or -1. If set, fold the two-sided time integral onto the data window using G_{ba}(-t) = ±conj(G_{ab}(t)); requires ts to start at t = 0. Use -1 for dcorrelator output (spin and electron alike), whose retarded -im prefactor flips the sign; the spectrum is then purely imaginary on the diagonal, -imag(diag)/2. See the inner fourier_kw method.

Returns

DynamicalCorrelators.fourier_rw — Function
fourier_rw(gf_rt, ts, ws; broadentype=(0.05, "G"), mthreads=nthreads(), ifsum=true, symmetrize=false)

Time Fourier transform from G(r, t) to G(r, ω) (real-space, frequency domain).

Arguments

  • gf_rt: Green's function (N_sites, N_sites, N_times).
  • ts: time points.
  • ws: frequency points.
  • broadentype: broadening specification, e.g., (0.05, "G") or (η, "GN") for the window-normalized Gaussian exp(-η·(t/tmax)^2).
  • mthreads: number of threads.
  • ifsum: if true, use simple summation; if false, use numerical integration.
  • symmetrize: false (default), true/+1, or -1. If set, use the conjugation symmetry G_{ba}(-t) = ±conj(G_{ab}(t)) (valid for ⟨A_a(t) A†_b(0)⟩ correlators in a time-translation invariant state) to fold the two-sided time integral onto the data window,

\[G_{ab}(r, \omega) = \int_0^T dt\, f(t) \big[ e^{i\omega t} G_{ab}(t) \pm e^{-i\omega t} G_{ba}(t)^* \big] .\]

With +1 each frequency slice is manifestly Hermitian in (a, b) with a real diagonal; with -1 it is manifestly anti-Hermitian with a purely imaginary diagonal. Either way, the unphysical truncation-induced component in the complementary quadrature is removed. Use -1 for dcorrelator output (spin and electron alike), whose retarded -im prefactor flips the conjugation sign; the spectral function is then -imag(diag)/2. ts must start at t = 0, and the result is the two-sided transform (twice the corresponding quadrature of the one-sided one).

Returns

Array of shape (N_sites, N_sites, length(ws)).

DynamicalCorrelators.conductivity — Function
conductivity(β, ∂Ek, Akw, ω_range; mu=0, ifsum=false)

Compute the DC optical conductivity from the single-particle spectral function using the Kubo formula in the DMFT approximation.

Reference: A. Georges, G. Kotliar, W. Krauth, and M. J. Rozenberg, Dynamical Mean-Field Theory of Strongly Correlated Fermion Systems and the Limit of Infinite Dimensions, Rev. Mod. Phys. 68, 13 (1996).

$\sigma = \sum_k (\partial E_k)^2 \int d\omega \, (-\partial f(\omega)) \, A^2(k, \omega)$

Arguments

  • β: inverse temperature 1/T.
  • ∂Ek: array of band velocity (energy derivative) for each k-point.
  • Akw: array of spectral functions A(k, ω) for each k-point (each element is a vector over ω).
  • ω_range: frequency grid.
  • mu: chemical potential (default: 0).
  • ifsum: if true, use simple summation; if false, use numerical integration.
