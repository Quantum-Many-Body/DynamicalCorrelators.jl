Algorithms

All core algorithms (DMRG, TDVP, IDMRG) are provided by MPSKit.jl, including Controlled Bond Expansion through the alg_expand keyword of DMRG and TDVP (OptimalExpand, SketchedExpand, RandExpand). On top of them, this package provides CBEExpand: the direct CBE selection assembled channel by channel from the Jordan-MPO structure, without materializing the two-site effective Hamiltonian — it is the default alg_expand of dmrg1!/dmrg_mix! and of the myDMRG1_CBE/myTDVP1_CBE constructors. The functions below are convenience constructors for the package's default algorithm configurations; drive them through MPSKit's find_groundstate, timestep/timestep!, and time_evolve.

Bond Expansion

DynamicalCorrelators.CBEExpand — Type
CBEExpand(; trunc, alg_svd = SafeDivideAndConquer(), rsvd = true)

Controlled Bond Expansion (direct selection) as an MPSKit changebond! bond-expansion algorithm, usable everywhere OptimalExpand is accepted — the alg_expand keyword of dmrg1!/dmrg_mix!, MPSKit's DMRG and TDVP drivers, or a standalone changebonds! call.

The expansion directions are dominant singular vectors of the projected two-site update. Jordan-MPO paths use factorized left/right complements and MPSKit's project_complement!/project_complement_right!, avoiding explicit nullspace bases and the full unprojected two-site vector. Other MPO types use MPSKit's OptimalExpand.

trunc bounds how much is added to each bond, not the total bond dimension that is kept. The projected block is normalized before the SVD, so only truncrank/truncspace have a robust meaning here.

With rsvd = true and a truncrank truncation, the SVD runs on a sketched matrix whose small dimension is current bond dimension + added rank (FiniteMPS.jl's randomized CBE): a random sketch compresses the large side of the projected block, an orthonormal basis of the sketch is built by QR/LQ, and only the compressed block is factorized. When the sketch would not compress (small bonds) the full block is used instead, so rsvd is a pure performance switch; the expansion itself stays deterministic in exact mode.

Fields

  • trunc::TruncationStrategy: how many directions are added to each bond
  • alg_svd: SVD algorithm (default: SafeDivideAndConquer())
  • rsvd::Bool: sketch the SVD target as described above (default: true)

DMRG drivers with bond-dimension schedules

DynamicalCorrelators.dmrg1! — Function
dmrg1!(ψ::AbstractFiniteMPS, H, truncdims::AbstractVector; kwargs...)

One-site finite DMRG with an explicit per-sweep bond-dimension schedule and optional bond expansion (CBE).

truncdims[i] is the target bond dimension kept after sweep i (one sweep is a left-to-right plus right-to-left pass), e.g. truncdims = [64, 64, 128, 512] runs two sweeps at D = 64, then one at 128 and one at 512. After the schedule is exhausted, tail sweeps at the final bond dimension continue until the per-sweep energy change satisfies |ΔE| ≤ etol (at most max_tailsweeps extra sweeps; a warning is issued if the tolerance is not reached).

Keyword arguments

  • alg_eigsolve: eigensolver for the one-site effective Hamiltonian (default: a fixed one-step Lanczos(krylovdim = 16, maxiter = 1, tol = 1e-8, ModifiedGramSchmidt(), eager = true); pass an explicit KrylovKit solver to override)
  • alg_svd: SVD algorithm (default: SafeDivideAndConquer())
  • alg_expand: bond-expansion strategy — an instance (used as-is for every sweep), a callable D -> alg (rebuilt from each sweep's target D), or nothing to disable expansion (plain one-site DMRG, which cannot grow the bond). The default is the callable D -> CBEExpand(; trunc = truncrank(ceil(Int, 0.1*D)), alg_svd), expanding by up to 10% of the target D before the gauge truncates back; MPSKit's OptimalExpand/SketchedExpand/RandExpand are drop-in alternatives
  • etol: convergence tolerance of the tail sweeps on the per-sweep energy change |ΔE| (default: 1e-8)
  • max_tailsweeps: maximum number of tail sweeps at the final bond dimension (default: 20; 0 disables tail sweeps, restoring the plain fixed schedule)
  • save: JLD2 checkpointing (default: true) — false writes nothing, true writes a rolling checkpoint after every sweep: the latest state atomically replaces the previous one in filename (keys ψ, E, ΔE, ϵ, ϵtrunc, D, sweep), so a killed run always leaves the newest completed sweep on disk; in addition, after every local update the touched site/bond tensors and the sweep bookkeeping are written atomically to an update-level checkpoint directory — joinpath(disk, basename(filename) * ".updates.d") when disk is a path (the transient scratch side, next to the environments), filename * ".updates.d" otherwise — so rerunning the same call after a kill resumes the interrupted sweep at the last completed update instead of restarting it, reusing the surviving disk-backed environments (in-RAM environments are simply rebuilt). The update-level checkpoint belongs to a specific (filename, truncdims) schedule; a mismatching call discards it and starts fresh. The directory is removed when the run finishes. A vector of sweep indices (e.g. save = [2, 4, 6]) switches to history mode, appending those sweeps as sweep_<i>_ψ/… entries (no update-level checkpointing in this mode)
  • filename: JLD2 checkpoint file (default: "default_dmrg1.jld2")
  • verbose: 0 silent, 1 per-sweep summary, >1 also per-move lines (default: true)
  • envs: environment cache — the default nothing builds a HalfFiniteEnvironments; pass MPSKit's environments(ψ, H, ψ) to run with the reference cache (e.g. for cross-checks). The cache type selects the local-update method, the per-sweep energy estimate and the memory bookkeeping of the sweep driver
  • disk: environment disk backing when the driver builds the cache — false (default) keeps environments in RAM, true serializes them to a node-local temporary directory (tempdir(), the same scheme as FiniteMPS.jl's disk = true), and a directory string uses that directory instead. When envs is supplied the cache is not rebuilt and disk only relocates the update-level checkpoint directory next to the environments (see save)
  • manual_gc: HalfFiniteEnvironments only (default: false): a full GC.gc(true) collection and memory report after every sweep. GC is deliberately not triggered per local update — with many states evolving concurrently, per-update collections make threads wait at GC safepoints

Returns (ψ, envs, E₀); see also dmrg1, dmrg2!.

DynamicalCorrelators.dmrg2! — Function
dmrg2!(ψ::AbstractFiniteMPS, H, truncdims::AbstractVector; kwargs...)

Two-site finite DMRG with an explicit per-sweep bond-dimension schedule.

truncdims[i] is the target bond dimension kept after sweep i (a left-to-right plus right-to-left pass); after the schedule, tail sweeps at the final bond dimension continue until |ΔE| ≤ etol (see dmrg1!).

Keyword arguments

Same as dmrg1!, except that there is no alg_expand (the two-site update grows the bond itself) and filename defaults to "default_dmrg2.jld2".

Returns (ψ, envs, E₀); see also dmrg2, dmrg1!.

DynamicalCorrelators.dmrg_mix! — Function
dmrg_mix!(ψ::AbstractFiniteMPS, H, truncdims_2site, truncdims_1site; kwargs...)
dmrg_mix!(ψ, H, truncdims; switch_D, kwargs...)

Hybrid finite DMRG driver: two-site sweeps (DMRG2 engine) for the small-D stages of the schedule, one-site sweeps with bond expansion (DMRG engine with alg_expand, i.e. CBE) for the large-D stages. Two-site updates grow the bond fast where sweeps are cheap; one-site updates are much cheaper per sweep at large D, where the CBE expansion only has to refresh a small fraction of D per sweep.

Two schedule forms: dmrg_mix!(ψ, H, [64, 128, 256], [512, 1024, 1024]) runs the first vector with DMRG2 and the second with DMRG1+CBE (sweep numbering and JLD2 checkpoints run continuously across both phases); the single-vector form dmrg_mix!(ψ, H, truncdims; switch_D = 256) splits truncdims at the last entry ≤ switch_D.

Tail sweeps at the final bond dimension (with the one-site engine) run until |ΔE| ≤ etol, exactly as in dmrg1!.

Keyword arguments

Same as dmrg1!; alg_expand applies to the one-site phase only and filename defaults to "default_dmrg_mix.jld2".

Returns (ψ, envs, E₀); see also dmrg_mix, dmrg2!, dmrg1!.

Default Algorithm Configurations

DynamicalCorrelators.myDMRG1 — Function
myDMRG1(; tol=1e-6, maxiter=100, krylovdim=16, alg_eigsolve=nothing)

Construct the default one-site DMRG algorithm used by this package.

The local eigensolver is a fixed one-step Lanczos with the given krylovdim budget (tol = 1e-8, ModifiedGramSchmidt(), eager early exit); pass alg_eigsolve explicitly for full manual control. tol and maxiter tune the outer DMRG stopping criterion and sweep count.

DynamicalCorrelators.myDMRG2 — Function
myDMRG2(; tol=1e-6, maxiter=50, trunc=truncrank(4096), krylovdim=16, alg_eigsolve=nothing)

Construct the default two-site DMRG algorithm.

trunc is passed as the SVD truncation scheme, so callers can use either a fixed-rank rule such as truncrank(D) or a tolerance-based rule. The default keeps at most 4096 states. The local eigensolver is a fixed one-step Lanczos with the given krylovdim budget (tol = 1e-8, ModifiedGramSchmidt(), eager early exit); pass alg_eigsolve explicitly for full manual control.

DynamicalCorrelators.myDMRG1_CBE — Function
myDMRG1_CBE(; tol=1e-6, maxiter=100, D=4096, delta=0.1, krylovdim=16, alg_eigsolve=nothing)

Construct the default one-site DMRG algorithm with Controlled Bond Expansion.

This is a thin wrapper around MPSKit's DMRG with alg_expand = CBEExpand(...): ahead of each one-site eigensolve the moving bond is enlarged by up to ceil(Int, delta*D) directions selected from the projected two-site update, and the truncating gauge (trunc = truncrank(D)) cuts the enlarged bond back to D when the center moves. Note that the trunc of CBEExpand counts the directions added per bond, so the former overexpansion factor delta enters through ceil(Int, delta*D). The local eigensolver is a fixed one-step Lanczos with the given krylovdim budget (tol = 1e-8, ModifiedGramSchmidt(), eager early exit); pass alg_eigsolve explicitly for full manual control.

source
DynamicalCorrelators.myTDVP1 — Function
myTDVP1(; krylovdim=24)

Construct the default single-site TDVP algorithm for finite-MPS time evolution.

This is the fixed-bond-dimension TDVP path from MPSKit. krylovdim controls the dimension of the Lanczos Krylov subspace used by the local time integrator. Unlike the DMRG eigensolvers, the time integrator is intentionally not adaptive: MPSKit's integrate dispatches on a concrete Lanczos/Arnoldi, and the required Krylov dimension (roughly dt x spectral width) barely changes during the evolution. Watch for "integrator failed to converge" warnings when taking large dt.

Fast Finite Engine

The finite-system drivers run on the package's lazy, optionally disk-backed environment manager; see The Finite Engine for the memory model and threading layout.

DynamicalCorrelators.HalfFiniteEnvironments — Type
HalfFiniteEnvironments(ψ::FiniteMPS, H; disk = false,
    hot = disk !== false, threaded_transfer = Threads.nthreads() > 1)

Memory-frugal environment manager for finite MPSKit calculations.

Keyword arguments

  • disk: false (default) keeps environments in RAM; true serializes them under a fresh random subdirectory of tempdir() — node-local storage, exactly the scheme of FiniteMPS.jl's disk = true (on cluster compute nodes honor TMPDIR); a string overrides the root directory (created when missing; each array gets its own random subdirectory underneath, so concurrent runs never collide). Disk backing trades I/O for memory at the largest bond dimensions; freed entries are deleted. An explicit string must point at fast node-local or burst-buffer storage.
  • hot: defaults to disk !== false. For disk-backed environments, cache the most recently read or written environment separately on each side. Writes replace the corresponding hot entry and frees invalidate it. Set hot=false for direct deserialization on every access; cold storage is unchanged.
  • threaded_transfer: build each environment from the Jordan-MPO channel list contracted across Julia threads (per-task local accumulation + locked merge, the same pattern as the threaded Hamiltonian). Defaults to Threads.nthreads() > 1 — it parallelizes a stage that is otherwise serial, so there is nothing to conflict with; the keyword remains only as an escape hatch for verification/debugging. NOTE: the assembled per-block BlockTensorMap relies on BlockTensorKit internals (SumSpace leg assembly) — validate with src/draft/verify_finiteengine.jl before relying on it.

The boundary environments are constructed exactly as in MPSKit.environments(ψ, H, ψ), and interior environments are built on first query, so HalfFiniteEnvironments(ψ, H) is a drop-in replacement for environments(ψ, H, ψ) in the DMRG drivers.

DynamicalCorrelators.fast_timestep! — Function
fast_timestep!(ψ, H, t, dt, alg::TDVP, envs::HalfFiniteEnvironments;
    imaginary_evolution = false, normalize = false, manual_gc = false,
    timeroutput = get_defaulttimer(), integration_stats = nothing)
fast_timestep!(ψ, H, t, dt, alg::TDVP2, envs::HalfFiniteEnvironments;
    imaginary_evolution = false, normalize = false, manual_gc = false,
    timeroutput = get_defaulttimer(), integration_stats = nothing)

One full TDVP sweep (left→right→left) on the fast finite engine, evolving ψ in place by dt starting from time t. Returns (ψ, envs).

manual_gc (default false) runs a full GC.gc(true) collection once at the end of each sweep when enabled — the same bookkeeping as the DMRG fast driver. (GC is deliberately not triggered per local update: with many states evolving concurrently, per-bond collections make the threads spend most of their time waiting at GC safepoints.) timeroutput records the two sweeps and, inside them, the expand (CBE), Hamiltonian-construction, integration/matvec and gauge/split sections; pass a shared TimerOutput to accumulate across steps. integration_stats can be a vector accepting push!; one NamedTuple per local integration then records its kind, site, direction, total/matvec times, Krylov dimension (for maxiter = 1), operator count, residual estimate and convergence status. Every effective Hamiltonian is released immediately after its local integration.

DynamicalCorrelators.configure_finite_engine! — Function
configure_finite_engine!(; blas_threads = 1, transformer_threads = nothing,
    manipulation_threads = nothing, svd_threaded = false, verbose = true)

Set the thread configuration recommended for the fast finite engine:

  • blas_threads: BLAS/LAPACK threads per call (default 1; the engine parallelizes above BLAS, so multi-threaded BLAS only adds contention)
  • transformer_threads: TensorKit recoupling (fusion-tree transformation) threads, or nothing to leave unchanged
  • manipulation_threads: TensorKit index-manipulation threads, or nothing to leave unchanged
  • svd_threaded: distribute the per-sector blocks of the gauge-step SVD over all Julia threads (default false, i.e. MPSKit's serial SVD)
  • vectorops_threaded: thread the Krylov-vector ops (inner/add!!/scale!!/ norm) on large TensorMaps over all Julia threads (default true) — this is what parallelizes Lanczos orthogonalization between matvecs, see algorithms/vectorops_threaded.jl
  • verbose: print the resulting configuration

Returns the number of Julia threads (the pool the engine actually uses).
